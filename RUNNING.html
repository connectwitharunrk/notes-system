Prerequisites

  • JDK 17+ — Gradle provisions a JDK 21 toolchain itself.
  • PostgreSQL 15+, or Docker to run it in a container.
  • Android Studio / an emulator for the Android target.
  • Xcode 15+ on macOS for the iOS target.
  • Windows PowerShell 5.1+ for the verification scripts.
Shell syntax Commands below use ./gradlew (macOS / Linux / Git Bash). In PowerShell or cmd on Windows, use .\gradlew.bat instead — everything after it is identical.

The client and the server are two separate Gradle builds, each with its own wrapper. Always run their commands from inside client/ and server/ respectively — there is no root-level build.

notes-system/
├── client/            Kotlin Multiplatform app  (own gradlew)
├── server/            Spring Boot backend       (own gradlew)
├── docs/              architecture reference
└── docker-compose.yml PostgreSQL + optional pgAdmin

1Start the database

The server will not boot without PostgreSQL. Easiest path is Docker, from the repository root:

docker compose up -d postgres

That starts postgres:17-alpine on port 5432 with database notes, user notes, password notes, and a persistent notes-pgdata volume. Check it came up healthy:

docker compose ps

Optional: pgAdmin

A pgAdmin container is defined behind a profile, so it only starts when asked for:

docker compose --profile tools up -d

Then open http://localhost:5050 — login dev@notes.local / notes.

Alternative: an existing local PostgreSQL

psql -U postgres -h 127.0.0.1 \
  -c "CREATE ROLE notes WITH LOGIN PASSWORD 'notes';" \
  -c "CREATE DATABASE notes OWNER notes ENCODING 'UTF8';"
On Windows, use 127.0.0.1 — not localhost localhost resolves to ::1 first, and a default PostgreSQL install rejects SCRAM auth over IPv6 while accepting it over IPv4. The symptom is a "password authentication failed" error that has nothing to do with the password.

2Run the server

cd server
./gradlew :app:bootRun          # PowerShell: .\gradlew.bat :app:bootRun

Flyway creates the whole schema on first run — no manual migration step. The server listens on port 8080.

Configuration

Every value below has a working development default, so you normally set none of them. Override via environment variables when you need to:

VariableDefaultPurpose
SERVER_PORT8080HTTP port
DB_URLjdbc:postgresql://127.0.0.1:5432/notesJDBC URL
DB_USERnotesDatabase user
DB_PASSWORDnotesDatabase password
JWT_SECRETdev-only placeholderHS256 signing key — must be overridden in production, minimum 32 bytes
 
# Example: run on a different port
SERVER_PORT=9090 ./gradlew :app:bootRun

# PowerShell equivalent
$env:SERVER_PORT = "9090"; .\gradlew.bat :app:bootRun

3Run the client

One shared codebase, three entry points. All commands run from client/.

Desktop (JVM)

cd client
./gradlew :desktopApp:run                # standard run
./gradlew :desktopApp:hotRun --auto      # hot reload while developing

Android

cd client
./gradlew :androidApp:installDebug       # build + install on running emulator/device
./gradlew :androidApp:assembleDebug      # build the APK only

The Android emulator reaches the host machine at 10.0.2.2, which the client already uses as its default base URL — an emulator needs no configuration. A physical device is on your LAN instead, so it needs the host's address passed at Koin startup:

initKoin(context, baseUrl = "http://192.168.x.x:8080")

iOS

Open client/iosApp/iosApp.xcodeproj in Xcode and run from there.

iOS is unverified iOS cannot be compiled on a Windows host, so the Keychain storage, NWPathMonitor, native SQLite driver and Darwin HTTP engine are written to the documented APIs but have never been built or run.
The client does not need the server The local database is the source of truth for the UI, so the app is fully usable with the backend switched off. Start the server when you want to exercise sync, auth or conflict handling.

4Verify it works

Unit tests — no database, no server

cd server
./gradlew :common:test :domain:test      # 85 backend unit tests

cd client
./gradlew jvmTest                        # 88 client tests

Most client tests need nothing; the integration tests among them do need the server running.

End-to-end HTTP scripts — server must be running

cd server
./scripts/verify-phase1.ps1     # 41 assertions: auth, sessions, rate limiting
./scripts/verify-phase2.ps1     # 61 assertions: notes, search, sync, conflicts

These are the quickest way to see the system actually work. The conflict section of verify-phase2.ps1 makes two devices disagree about the same note and shows both versions surviving rather than one overwriting the other.

5Package the desktop app

cd client
./gradlew :desktopApp:packageDistributionForCurrentOS

Produces an .msi, .dmg or .deb under client/desktopApp/build/compose/binaries/main/, depending on the host OS.

Troubleshooting

SymptomCause & fix
"password authentication failed" for user notes Usually IPv6, not a wrong password. Use 127.0.0.1 instead of localhost in DB_URL.
Server exits at startup with a connection refused PostgreSQL isn't up yet. docker compose up -d postgres, then docker compose ps to confirm it's healthy.
Port 8080 already in use Start on another port with SERVER_PORT, and point the client's baseUrl at it.
Hibernate schema validation failure ddl-auto is validate — Flyway owns the schema. If migrations were interrupted, drop the volume and start clean: docker compose down -v && docker compose up -d postgres. This deletes all local data.
Android app can't reach the server Emulator: host is 10.0.2.2 (already the default). Physical device: pass your LAN IP as baseUrl and make sure the firewall allows port 8080.
./gradlew not recognised on Windows Use .\gradlew.bat, or run the command from Git Bash.
Password-reset email never arrives Expected in development — the reset token is printed to the server log instead of being emailed.
